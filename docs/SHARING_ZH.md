# 先本地、后发布与来源记录
先完成本地工程、测试和双语文书，再刷新目录清单与哈希。之后才把同一份允许分享的快照同步到独立 Git checkout，用 PowerShell／Git 命令行提交和推送。最后核对远端 HEAD，并比较本地与 checkout 的逐文件哈希，不使用网页上传。

本地项目嵌套在另一个 Git 仓库下面，不能在父级 EE475 目录不加范围地 git add。独立发布 checkout 用来防止混入其他工程。正常推送前检查远端有没有新提交，不强制覆盖。

包含：当前源码／测试、发布固件、参考信标、播放器 APK／源码、原始项目参考资料、双语说明／报告、汇总指标，以及唯一的最终组合模板和对应 ZIP。
排除：原始麦克风录音、逐次串口日志／预热字节、私人导入音频、签名密钥／密码、机器配置、SDK／工具链缓存、构建目录、板卡原固件备份。

从活跃目录移出的历史文件保存在项目外本地归档，记录原路径、目标路径和 SHA256。首次清理共移动并核验 418 个文件。迁移清单含本机路径，因此不上传；随后覆盖的旧说明也保留本地副本。原组合 ZIP 留在外部备份，新组合 ZIP 只调整说明和清单，52 个非文书文件逐字保持一致。

根哈希清单不包含自身，但覆盖生成的目录清单；所有修改结束后才验证。模板 ZIP 逐成员与目录比对。参见[文件清单](FILE_CATALOG_ZH.md)、模板来源清单及[阶段报告](../reports/communication-2026-11-12/REPORT_ZH.md)。

发布准备命令：
```powershell
python tools/refresh_catalog.py
python tools/verify_release.py
```
这些命令本身不上传。得到发布授权后，再检查独立 checkout 的 Git 差异、提交、推送并核对远端提交。运行时本地日志不属于同步范围。
