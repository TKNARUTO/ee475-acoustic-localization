# Repository and archive contents

The GitHub repository and the team ZIP contain the same selected project files. Each published file is listed in FILE_CATALOG.md and FILE_CATALOG.csv. SHA256SUMS.txt verifies content. The source directory layout is preserved so imports and launch paths remain meaningful.

Included: current desktop/firmware source, current RAM firmware, generated phone beacon/probe files, Android source and signed development APK, illustrated reports, hardware references, validation scripts, current stage notes and historical source/documentation. Two reviewed code-only baseline ZIPs are retained because tests read them.

Local only: original microphone recordings, automatic captures, per-run logs, raw trial folders, local import selections, SDKs/build caches, IDE settings, machine toolchain settings, signing keys, repeated legacy release/archive ZIPs and local absolute-path migration indexes. Exclusion is not deletion. The full local backup in delivery preserves the project before handoff; the final complete local ZIP preserves the organized state. Neither is intended as a GitHub upload.

Some historical documents refer to excluded recordings or old absolute paths. Those links are historical provenance, not a claim that the files exist in a fresh clone. The owner's FILE_INDEX.txt and docs/LOCAL_FILE_INDEX.csv resolve the complete local collection; GitHub FILE_CATALOG.md resolves the published subset. Reports retain derived plots and conclusions without publishing the original microphone stream.

No source licence has been selected. Keep the repository private for team handoff unless the owner decides otherwise. Third-party board documents retain their own rights and notices. APK is development-signed; the private signing key is deliberately not part of the project package.
