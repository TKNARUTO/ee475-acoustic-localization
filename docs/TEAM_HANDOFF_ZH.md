## 当前约定
Pico v0.2-link_diag，固定 HF2 18–22 kHz 间隔信标，48 kHz／4096 点，整数 FFT FAST；whitening／cache 实验选项关闭；只用 core0。ESP 接收器 v1.1，经典 NodeMCU-32S，Arduino esp32 core3.3.12。UART0↔UART2 三线，115200 8N1。B 包即使 valid 为零，也可能包含有限诊断角度／质量，具体以[协议说明](../esp32-link/gap_receiver/README_ZH.md)为准，不能照搬旧 DOA 示例。

独立 Pico 监视器没有旧电脑算法的任意信标导入或原始频谱功能；这些保留在[最终组合模板](../legacy/pico+computer%20combo%20sensoring%20version/README_ZH.md)。不要把它的 RAM 固件和启动器混入当前 Flash 版本。

## 本阶段改动
- 发送元数据对应实际成功排入 UART 的 B 包，发送失败不再声称已经发送新结果。
- 保留过期／未确认但有限的拟合供诊断，控制有效位与有效期不变。
- ESP 显示当前收到的字段，不用旧目标角度冒充本次接收。
- 按会话／序号关联 B 的 ACK，hello 和重复 ACK 不进入往返计时。
- 保存启动原始字节，并在正式记录前隔离开端积压；正式阶段不去重。
- 核验 Pico 持久 Flash 和桌面 Arduino sketch 烧录；测试软重启以及无 Pico 电脑读取。
- 分开平台文书、测试、固件和中英文报告，legacy 只保留最终组合模板。

没有改阵列接线、信标波形，没有加入电机控制或大角度阻止逻辑。实验性数值优化仍暂停。

## 下一阶段优先项
1. 读[当前报告](../reports/communication-2026-11-12/REPORT_ZH.md)和[阶段笔记](../pico-standalone/COMMUNICATION_NOTEBOOK_ZH.md)。
2. 用当前 Flash 做已知角度的手机复测。此前正向手机测试用同源码／选项的 RAM 镜像，后续 Flash 检查是背景测试。
3. 实测声学起点到输出的延迟和受控角度误差。包一致不等于物理方向准确。
4. 获准后再优化计算／调度到 0.2–0.5 秒，处理确认间隔，保留年龄语义。
5. 用负例和录音证据解决已知错码误触发。
6. 再制定有实测依据的控制周期预算、坐标校准、测距接口、停止策略和引脚分工。

改动前写清范围和验收条件；改动后同步中英文笔记、README、清单和哈希。先更新本地，再用 PowerShell／Git 命令行上传，核对可分享文件哈希和远端提交。不要把父级工作区整体加入 Git。长期约束见 AGENTS.md。
