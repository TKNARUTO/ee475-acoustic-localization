实线是当前功能，运动控制是后续工作。本分支的声学 FFT／拟合不在电脑运行；旧组合模板则通过 USB 传 PCM，在电脑计算方向。

## 数据流程
Pico 每声道采集 4096 点，匹配固定 HF2 参考，寻找声道到达时间，做阵列几何拟合，再进行编码确认和结果年龄检查。目前只用 120 MHz 的 core0。UART 报文包含会话、序号、年龄、有效位、角度、质量，并由 CRC16 保护。ESP 检查帧、CRC、会话、序号和新鲜度后返回 ACK。USB 显示收到的实际字段，和控制目标状态分开。

无效包仍可能携带有用的有限诊断角度，但不能据此转向。没有拟合时发送零角度／质量，但真实的 0° 方向也合法。当前八字段协议没有 fit-valid 或具体原因，接收者必须看有效位与过期状态，不能用角度是否为零判断。详见[协议](../esp32-link/gap_receiver/README_ZH.md)。

Pico 的新鲜度上限是 480 ms。ESP 加上 20 ms 通信预算，总年龄超过 500 ms 就让目标过期。重复包、旧序号或错误会话不能刷新旧目标。ACK 往返耗时含主循环轮询，并非纯线路延迟。电脑的 Set Display Front 只改变显示坐标；小车控制需要单独规定阵列到车头的校准关系。

## 后续控制循环伪代码
```text
收到新的合法方向包：
    如果目标有效且包含传输的年龄未超过有效期：
        目标 = 阵列坐标转换到车头坐标(方向)
        保存原始测量时刻
    否则：
        让目标无效

固定周期控制任务：
    读取测距和障碍信息
    如果急停、目标过期或无效：
        请求安全停止
    否则：
        误差 = 目标与当前朝向的最短带符号角差
        输出 = 有速率限制的控制器(误差, 距离)
        应用电机输出限制
```
这只是方案，尚未烧入。动电机前必须校准正负方向与车头。可限制电机指令变化率，但不能把真实大幅转向信号直接屏蔽。

## 预计问题与检查
| 问题 | 表现 | 检查／边界 |
|---|---|---|
| 旧结果当新结果用 | 朝旧位置转向 | 保留测量年龄，不能在画箭头时重置时间 |
| 确认间隔超限 | 有拟合却一直无效 | 当前约 885 ms 周期超过 750 ms 确认间隔，优先优化耗时 |
| GPIO 被电机或 PSRAM 占用 | 串口异常／控制冲突 | 明确预留引脚，本次 NodeMCU 的 16／17 空闲 |
| 角度正负／声道映射相反 | 通信正常但转反 | 已知角度扫描；显示偏移不等于 UART 校准 |
| 重启／序号回绕 | 旧包恢复旧目标 | 现有协议测试覆盖；新会话清除目标 |
| 打开 USB 时积压 | 开头重复或截断日志 | 有界启动原始记录＋一次清缓冲＋换行对齐，正式阶段不去重 |
| 反射／窄频模糊 | 跳方向或时差不一致 | 记录真实角度与诊断证据，不仅因转角大就阻止 |
| 错码误接受 | 干扰触发 | 已知错码负例仍失败，未达到抗干扰认证 |
| 控制逻辑阻塞 DSP | DMA 服务超时／延迟增加 | 留意 10.667 ms 块期限，实测最坏耗时、栈和中断冲突 |
| 手机导入不匹配音频 | 有声音但无定位 | 当前 Pico 固定模板，只用配套 HF2 |
| 雷达圆圈被当测距 | 跟车距离错误 | 圆圈仅作显示，距离另接传感器 |

## 为什么先完成通信
此前手机测试的 Pico DSP 约 789 ms、周期约 885 ms，最终拟合约 6 ms。仅把最终拟合交给 ESP 并不能把延迟减半。ACK 往返约 7–8 ms，也远小于计算耗时。用户选择保留当前处理器组合，先完成通信，再继续 FFT／双核优化。

七声道 PCM 要 672 kB/s，115200 UART 只有约 11.52 kB/s 有效能力，不能直接承载；传方向摘要能避免这类带宽问题。静态内存有剩余不代表实时任务一定排得下，目前没有完整 CPU 利用率和运行时栈／堆高水位测量。
