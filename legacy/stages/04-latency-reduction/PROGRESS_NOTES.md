# RX2 阶段汇报：正常刷新延迟降低

日期：2026-10-27

这次把设备端计时加进去后，发现原来除了传音频，Pico 每包算 CRC 还要花约 22 毫秒。之前报告里电脑 CRC 不到 0.1 毫秒，说的是电脑这边，两个环节现在已经分清。

主要改了两处：USB 用更合适的缓冲批量发送；Pico 的 CRC 改成查表计算，校验规则不变。实测传输约 102 → 70 毫秒，设备 CRC 约 22.5 → 7.2 毫秒。相同格式的 100 包测试中，整包等待约 208 → 164 毫秒，减少约 21%。界面实际检测刷新约每秒 5.35 次。

CRC 标准向量、音频包完整性、坏包恢复和界面检查都通过了。也测试了旧版程序自动更新到新 RAM 固件，默认启动入口可以继续用。固件和配套 ELF 已一起更新，原版和实验版另存了备份。

这次没有改定位算法、接线或手机音频，没有加回大幅转向限制。没有手机播放实录，所以不能说反向跳变、时差不一致或远距离定位已经解决。正常数据链路已经变快，下一次需要你播放原来的 20 kHz 文件，看实际箭头响应，再留一段固定位置的原始数据。

程序已重新打开，扫描关闭。你方便测试时直接点 Start Scan。详细数字、改动和文件位置见 [README](README.md)、[改动详解](CHANGE_DETAILS.md) 与 [阶段报告](../../reports/latency-reduction-2026-10-27/LATENCY_REDUCTION_ZH.md)。
